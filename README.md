# Stat Course Pilot

Двуязычный Quarto-проект для онлайн-книги по статистическому анализу.

## Structure

- `ru/book/` — русская книга
- `ru/slides/` — русские слайды
- `en/book/` — английская книга
- `en/slides/` — английские слайды
- `shared/` — общие стили, библиография, изображения, `notebooks/common` и PDF-настройки
- `scripts/` — служебные скрипты

## Build

```bash
python -m pip install -r requirements.txt
make site
```

Полный сайт собирается в `_site/` с деревом `ru/book`, `ru/slides`,
`en/book`, `en/slides`. Цель `make site` публикует HTML и PDF русской книги,
а также отдельные PDF готовых глав. EPUB собирается и проверяется отдельной
целью, но на сайт не публикуется. Python нужен для выполняемых Quarto-блоков,
фигур, QR-кодов и подготовки EPUB.

Push в `main` автоматически публикует сайт. `workflow_dispatch` позволяет
повторить публикацию вручную. Цель `make ci-setup` устанавливает Python-зависимости
и TinyTeX, если на runner ещё нет LuaLaTeX.

Дополнительные цели для отдельных форматов можно посмотреть командой
`make help`.

## Notes

- обе книги собираются через `lualatex`;
- в английской книге после содержательных глав идут companion notebooks;
- задачи русской книги подключаются из общих include-файлов курса;
- `make ru-pdf` и `make en-pdf` собирают PDF отдельно от сайта;
- `make ru-chapters` собирает полную русскую PDF-книгу и выделяет готовые
  главы в `_site/ru/book/chapters/`; список публикуемых глав задаётся переменной
  `RU_PDF_CHAPTERS` в `Makefile`;
- `make ru-epub` и `make en-epub` собирают EPUB отдельно от сайта;
- русская книга подключает общую книжную основу NeutrinoHit из
  `ru/book/assets/styles/neutrinohit-book.css` и сохраняет предметные правила в
  `ru/book/assets/styles/book.css`.

## Правила для авторов

Требования к научной проверке, языку, структуре главы, источникам,
перекрёстным ссылкам, апплетам и сборке собраны в
[`docs/book-authoring-guide.md`](docs/book-authoring-guide.md). Эти правила
применяются ко всем новым главам и обновляются одновременно с общими приёмами
оформления и сборки.

## Схемы процессов

Линейные процессы задаются семантическими блоками Markdown, а не сырой HTML-разметкой:

```markdown
:::: {.process-flow aria-label="Название процесса"}
::: {.process-step label="01" title="Первый шаг"}
Произвольный текст, формулы, ссылки и другие блоки Pandoc.
:::

::: {.process-step label="02" title="Следующий шаг"}
Продолжение процесса.
:::
::::
```

Порядок блоков задаёт связи между шагами. Общий фильтр и стили автоматически
строят адаптивную схему для HTML/EPUB и вертикальную схему для PDF. Если
`label` не задан, шаги нумеруются автоматически. До четырёх шагов HTML-схема
строится горизонтально; более длинные процессы становятся вертикальными.
Вертикальную раскладку можно включить явно атрибутом `layout="vertical"` у
`process-flow`.
