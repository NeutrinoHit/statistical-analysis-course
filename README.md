# Stat Course Pilot

Двуязычный Quarto-проект для онлайн-книги по статистическому анализу.

## Structure

- `index.qmd`, `_quarto.yml`, `styles.css` — страница курса; `applets.html` и
  `robots.txt` копируются на сайт как есть
- `ru/book/` — русская книга
- `ru/slides/` — русские слайды
- `en/book/` — английская книга
- `en/slides/` — английские слайды
- `shared/` — общие стили, библиография, изображения, `notebooks/common` и PDF-настройки
- `scripts/` — служебные скрипты

## Build

```bash
python -m pip install -r requirements.txt
make site
```

Сайт собирается в `_site/`: страница курса, апплеты и слайды `ru/slides`,
`en/slides`. Книги RU и EN на сайте не публикуются: их HTML, PDF и EPUB
собираются только отдельными целями (`make ru-html`, `make ru-pdf`,
`make ru-chapters`, `make ru-epub` и такими же для EN), и `make site`
проверяет, что в `_site` книжных каталогов нет. Python нужен для выполняемых
Quarto-блоков, фигур, QR-кодов и подготовки EPUB.

Push в `main` автоматически публикует сайт. `workflow_dispatch` позволяет
повторить публикацию вручную. Цель `make ci-setup` устанавливает
Python-зависимости; TeX для сайта не нужен.

Дополнительные цели для отдельных форматов можно посмотреть командой
`make help`.

## Notes

- обе книги собираются через `lualatex`;
- в английской книге после содержательных глав идут companion notebooks;
- задачи русской книги подключаются из общих include-файлов курса;
- тринадцать опубликованных русских глав соответствуют лекциям 01–13; при
  разделении лекции одновременно разделяются глава и общий файл задач;
- будущие главы и задачи хранятся без номера в `ru/book/planned/` и
  `_includes/exercises/planned/` и не входят в публикацию;
- `make ru-pdf` и `make en-pdf` собирают PDF; на сайт они не попадают;
- `make ru-chapters` собирает полную русскую PDF-книгу и выделяет готовые
  главы в `_site/ru/book/chapters/`; список публикуемых глав задаётся переменной
  `RU_PDF_CHAPTERS` в `Makefile`; сейчас отдельный PDF создаётся для каждой из
  тринадцати опубликованных глав;
- отдельные PDF сохраняют нумерацию полной книги, но не содержат оглавлений
  следующих частей и задней обложки;
- `make ru-epub` и `make en-epub` собирают EPUB отдельно от сайта;
- обе книги подключают общую книжную основу NeutrinoHit из
  `<lang>/book/assets/styles/neutrinohit-book.css` и `assets/filters/` и сохраняют
  предметные правила в `<lang>/book/assets/styles/book.css`; английский
  `book.css` совпадает с русским, а карточки companion notebooks описаны в
  `en/book/assets/styles/notebooks.css`;
- английская книга подключает ноутбуки через симлинк
  `en/book/notebooks -> shared/notebooks/common`; Pandoc открывает Lua-фильтры
  из реального каталога ноутбука, поэтому `shared/notebooks/assets` указывает на
  `en/book/assets`, а PDF собирается с `keep-tex: true` (файл
  `en/book/statistical-analysis.tex` в Git не входит);
- `shared/styles/book.css` и `shared/latex/common-pdf.tex` использует отдельная
  сборка ноутбуков (`scripts/render_notebook_standalone.sh`); в
  `common-pdf.tex` также определены макросы `\E`, `\Var`, `\cov`, `\dd`, которые
  обе книги получают через свой `_metadata.yml`.

В Git сохраняются иллюстрации из `ru/book/assets/figures/`, используемые в
публикации; они обновляются генераторами, без ручного редактирования.
LaTeX-версии книг (`ru/book/statistical-data-analysis.tex`,
`en/book/statistical-analysis.tex`) создаёт сборка с `keep-tex`; в Git они не
входят. Готовые PDF и HTML в `_site/`, а также кэши в коммит не включаются.

## Правила для авторов

Лицевая и задняя обложки русской HTML/PDF-книги хранятся как публикуемые
векторные ресурсы в `ru/book/assets/covers/`. Редактируемые исходники и
генераторы каноничны в `neutrinohit-map/assets/books/covers/`; порядок
обновления описан в `ru/book/assets/covers/README.md`. Сборка книги использует
локальные копии и не требует соседнего проекта или шрифтов обложки.
В HTML оборот раскрывается на стартовой странице, в PDF он завершает книгу.
При извлечении отдельных глав оборот исключается.

Требования к научной проверке, языку, структуре главы, источникам,
перекрёстным ссылкам, апплетам и сборке собраны в
[`docs/book-authoring-guide.md`](docs/book-authoring-guide.md). Эти правила
применяются ко всем новым главам и обновляются одновременно с общими приёмами
оформления и сборки.

## Схемы процессов

Линейные процессы задаются семантическими блоками Markdown, а не сырой HTML-разметкой:

```markdown
:::: {.process-flow aria-label="Название процесса"}
::: {.process-step label="01" title="Первый шаг"}
Произвольный текст, формулы, ссылки и другие блоки Pandoc.
:::

::: {.process-step label="02" title="Следующий шаг"}
Продолжение процесса.
:::
::::
```

Порядок блоков задаёт связи между шагами. Общий фильтр и стили автоматически
строят адаптивную схему для HTML/EPUB и вертикальную схему для PDF. Если
`label` не задан, шаги нумеруются автоматически. До четырёх шагов HTML-схема
строится горизонтально; более длинные процессы становятся вертикальными.
Вертикальную раскладку можно включить явно атрибутом `layout="vertical"` у
`process-flow`.
